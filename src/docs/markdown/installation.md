# Installation

<p class="text-lg text-aeblack-500 mb-8">This page is for projects that use <strong>plain HTML</strong> — no React, no Vue, no Angular. The AEGOV Design System ships as <a href="https://developer.mozilla.org/en-US/docs/Web/Web_Components">Web Components</a>, which means every <code>aegov-*</code> tag works in any HTML page once two files are loaded: a JavaScript bundle that registers the custom elements, and a CSS file that styles them. Two methods are documented below — pick whichever fits your project: <strong>Method A — copy build files to public assets</strong> (no bundler required, plain <code>&lt;script&gt;</code> + <code>&lt;link&gt;</code> tags) or <strong>Method B — import from the npm package</strong> (when you already use a bundler like Vite, Parcel, Webpack, PostCSS, or Tailwind v4).</p>

## What you need to load

Every AEGOV page needs three things in the document `<head>`:

| File | Purpose | Path inside the package |
| --- | --- | --- |
| `aegov.esm.js` | Modern ESM bundle — registers custom elements, lazy-loads each component on first use. Loaded with `<script type="module">`. | `dist/aegov/aegov.esm.js` |
| `aegov.js` | Legacy IIFE bundle for browsers without ES modules. Loaded with `<script nomodule>`. | `dist/aegov/aegov.js` |
| `aegov.css` | Compiled stylesheet — colors, typography, every component's styles. | `dist/aegov/aegov.css` |

These are the **build artifacts** generated by the design system's `npm run build` and shipped inside the npm package's `dist/` folder.

---

## Method A — copy build files to public assets

Use this when you want a pure HTML setup with no bundler — straight `<script>` and `<link>` tags pointing at files served from your own web root.

### 1. Install the npm package

In your project root:

```bash
npm install @aegov/design-system
```

(Or `yarn add` / `pnpm add` — same result.)

This downloads the package into `node_modules/@aegov/design-system/`. The build artifacts live at `node_modules/@aegov/design-system/dist/aegov/`.

---

### 2. Copy the build folder to your public assets

The browser needs to fetch the files at runtime, so they must be served from your web root. Copy `dist/aegov/` into your project's public/static directory.

If your public directory is `public/`, run:

```bash
cp -R node_modules/@aegov/design-system/dist/aegov public/aegov-design-system
```

Or if you prefer a single command on every install, add a postinstall script to your `package.json`:

```json
{
  "scripts": {
    "postinstall": "cp -R node_modules/@aegov/design-system/dist/aegov public/aegov-design-system"
  }
}
```

After this, your public folder contains:

```
public/aegov-design-system/
  aegov.esm.js
  aegov.js
  aegov.css
  aegov-input.entry.js
  aegov-button.entry.js
  …
```

The `*.entry.js` files are the per-component lazy chunks that `aegov.esm.js` fetches on demand. Keep the whole folder together — don't copy individual files.

---

### 3. Reference the files in your HTML

Add these three lines to the `<head>` of any HTML page that uses AEGOV components:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My AEGOV page</title>

    <!-- 1. Modern browsers: load the ES module bundle -->
    <script type="module" src="/aegov-design-system/aegov.esm.js"></script>

    <!-- 2. Legacy browsers: load the IIFE bundle -->
    <script nomodule src="/aegov-design-system/aegov.js"></script>

    <!-- 3. Stylesheet -->
    <link rel="stylesheet" href="/aegov-design-system/aegov.css" />
  </head>
  <body>
    <!-- Components go here -->
  </body>
</html>
```

The leading `/` assumes your public folder is served as the web root. Adjust the path if your project serves under a sub-path (e.g. `/static/aegov-design-system/aegov.esm.js`).

---

### 4. Use a component

Drop any `aegov-*` tag directly into the body — no `customElements.define` call needed. The ES module bundle handles registration automatically:

```html
<body>
  <main class="aegov-container">
    <aegov-button>Submit application</aegov-button>
  </main>
</body>
```

Open the page in a modern browser — the button renders styled.

## Method B — import from the npm package (bundler required)

Use this when your project already runs a CSS or JavaScript build step — Vite, Parcel, Webpack, Rollup, esbuild, PostCSS, or Tailwind v4. The bundler resolves `@aegov/design-system/...` specifiers to files inside `node_modules/` and emits a final bundle that the browser loads. **No `cp -R` step needed** — the bundler handles asset copying for you.

### 1. Install the npm package

```bash
npm install @aegov/design-system
```

### 2. Import the stylesheet from your CSS

In any CSS file your bundler processes (e.g. `src/styles.css`, `src/main.css`):

```css
@import "@aegov/design-system/css";
```

That single line resolves to `node_modules/@aegov/design-system/dist/aegov/aegov.css` via the package's `exports` map. Vite, Parcel, Webpack (with `css-loader`), PostCSS, and Tailwind v4 all support this resolution out of the box.

If you also use **Tailwind v4** and want the design system's design tokens as Tailwind utilities (`bg-primary-600`, `text-aered-700`, etc.), import the theme alongside Tailwind's base:

```css
@import "tailwindcss";
@import "@aegov/design-system/theme";
@import "@aegov/design-system/css";
```

### 3. Import the JavaScript bundle from your entry script

In your JavaScript or TypeScript entry file (e.g. `src/main.ts`, `src/index.js`):

```js
import "@aegov/design-system/dist/aegov/aegov.esm.js";
```

This loads the lazy-load runtime which auto-registers every `aegov-*` custom element on first use. Once this module evaluates, you can drop any AEGOV tag into your HTML and it renders.

> **Why the explicit subpath?** The bundle file path is the most stable specifier — it's a real published artifact at a fixed location. The package barrel (`import "@aegov/design-system"`) and the `loader` subpath are intended for tree-shakeable imports of individual components, not the lazy-load runtime.

For a tree-shakeable single-component import (skips the lazy loader and bundles only the components you reference):

```js
import { defineCustomElement as defineAegovButton } from "@aegov/design-system/components/aegov-button";
import { defineCustomElement as defineAegovInput }  from "@aegov/design-system/components/aegov-input";

defineAegovButton();
defineAegovInput();
```

This is the same path the React wrapper uses internally. Use it when bundle size matters and you only need a handful of components.

### 4. Use a component

The HTML markup is identical to Method A — just drop the tags into your template:

```html
<main class="aegov-container">
  <aegov-button>Submit application</aegov-button>
</main>
```

The bundler outputs the CSS and JS to your `dist/` (or whatever your build outputs); the browser loads them like any other bundled asset.

### Bundler-specific notes

| Tool | Notes |
| --- | --- |
| **Vite** | Works out of the box. CSS `@import` and JS `import` both resolve via Vite's dev server and Rollup-based build. |
| **Parcel** | Works out of the box. |
| **Webpack** | CSS resolution requires `css-loader`. JS imports work with default config. |
| **Tailwind v4** | Use the `@import "@aegov/design-system/theme"` line in any CSS file processed by Tailwind. The `@theme` block in the imported file extends Tailwind's color palette and font stack. |
| **PostCSS standalone** | Add `postcss-import` to resolve `@import` from `node_modules/`. |
| **Rollup** | Add `@rollup/plugin-node-resolve` for JS imports; CSS via `rollup-plugin-postcss`. |

## Full example — a "Submit application" button

This is a complete, copy-pasteable HTML page that loads the design system from local public assets, renders a primary button, and wires a click handler.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>AEGOV button example</title>

    <script type="module" src="/aegov-design-system/aegov.esm.js"></script>
    <script nomodule src="/aegov-design-system/aegov.js"></script>
    <link rel="stylesheet" href="/aegov-design-system/aegov.css" />

    <style>
      body {
        font-family: system-ui, sans-serif;
        max-width: 480px;
        margin: 4rem auto;
        padding: 1rem;
      }
    </style>
  </head>
  <body>
    <h1>My service application</h1>

    <aegov-button id="submit-btn" variant="primary" appearance="solid" size="lg">
      Submit application
    </aegov-button>

    <p id="status" style="margin-top: 1rem;"></p>

    <script type="module">
      const button = document.getElementById('submit-btn');
      const status = document.getElementById('status');

      button.addEventListener('aegovButtonClick', async () => {
        button.isLoading = true;
        button.isDisabled = true;
        try {
          // Replace with a real submission endpoint
          await new Promise((resolve) => setTimeout(resolve, 1500));
          status.textContent = 'Submitted successfully.';
        } catch (err) {
          status.textContent = 'Submission failed.';
        } finally {
          button.isLoading = false;
          button.isDisabled = false;
        }
      });
    </script>
  </body>
</html>
```

What's happening:

1. The three lines in `<head>` register every AEGOV custom element and load the stylesheet.
2. `<aegov-button>` renders directly with typed props as kebab-case HTML attributes (`variant="primary"`, `appearance="solid"`, `size="lg"`).
3. The component emits an `aegovButtonClick` custom event on click — listened to with `addEventListener`.
4. State props like `isLoading` and `isDisabled` can be set as JavaScript properties on the element (`button.isLoading = true`). They map 1:1 to the `is-loading` / `is-disabled` HTML attributes.

Open the file in a browser — click the button, watch the spinner, see the status update.

## Setting properties from HTML vs JavaScript

Web components accept props two ways:

```html
<!-- As HTML attributes — kebab-case, string values -->
<aegov-button is-disabled="true" size="lg" variant="primary">Click</aegov-button>
```

```js
// As JavaScript properties — camelCase, native types
const btn = document.querySelector('aegov-button');
btn.isDisabled = true;
btn.size = 'lg';
btn.variant = 'primary';
```

Use HTML attributes for the initial render; use JavaScript properties for runtime state changes (loading, disabled, value, etc.).

## Listening to component events

Every component has its own custom events, all prefixed with `aegov`. Examples:

```js
input.addEventListener('aegovInputChange', (e) => console.log(e.detail.value));
button.addEventListener('aegovButtonClick', (e) => console.log(e.detail));
checkbox.addEventListener('aegovCheckboxChange', (e) => console.log(e.detail.checked));
```

Event names are listed in each component's docs page (look in the left navigation).

## Where to next

Once installation works, here's what to read next based on what you're building:

- **Forms** — every form component (input, textarea, select, checkbox, radio, toggle, range, OTP, fileupload, datepicker) ships a unified validation API. Read [Validation Surface](validation-overview.html) for the props (`is-invalid`, `error-message`, `hint`), the `aegovValidate` event, and the imperative `validate()` and `setCustomValidity()` methods. Then read [Bring Your Own Validator](validation-byo.html) for hand-rolled validation patterns (no external library required) covering single-field, cross-field, server-side, and submit-time validation.
- **Tailwind theme** — if you also use Tailwind CSS v4 in the same page, you can import the design system's design tokens (`@import "@aegov/design-system/theme";`) so colors and fonts become Tailwind utilities (`bg-primary-600`, `text-aered-700`, etc.). Skip this if you only need the components.
- **Per-component reference** — every component has its own page in the left navigation listing props, events, methods, accessibility notes, and full HTML examples. Start with [Button](aegov-button.html), [Input](aegov-input.html), and [Form Field](aegov-form-field.html) for the most common patterns.
- **Using a JavaScript framework** — if you eventually move to React, see [Using with React](using-with-react.html) for typed wrappers, JSX-friendly props, and refs. Vue and Angular wrappers are planned.

## Troubleshooting

### Component renders as plain text or unstyled

The most common cause is the stylesheet not loading. Verify in DevTools → Network that `aegov.css` returned `200`. The component renders before the JS bundle finishes if your script tag is missing — check the console for module-loading errors.

### `Failed to fetch …entry.js` errors

The lazy-loaded per-component chunks must be served from the same folder as `aegov.esm.js`. If you only copied `aegov.esm.js` (not the whole `dist/aegov/` folder), the chunks 404. Re-run the copy step from Step 2.

### Components work in Chrome but not Safari

Safari ≥16.4 is required. The design system relies on `ElementInternals` and FormAssociated custom elements for form components — older Safari lacks these. Older browsers can still load the bundle but form-component validation will degrade gracefully.

### Build version mismatch

Make sure all three files (`aegov.esm.js`, `aegov.js`, `aegov.css`) come from the same release. Don't mix files from different versions — they're built together.
