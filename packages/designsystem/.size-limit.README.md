# Bundle budget notes

size-limit tracks `dist/aegov/aegov.css` only. JS bundles intentionally not enforced via size-limit.

## Why not JS?

Stencil's output is a lazy-load runtime (`dist/aegov/aegov.esm.js` ~12kb)
plus per-component chunks (`dist/aegov/*.entry.js` ~5–15kb each). When
size-limit analyzes any JS entry, esbuild bundles the entire `@stencil/core`
runtime (~80kb min) into the measurement, producing a misleading ~90–140kb
size for every chunk regardless of the chunk's actual on-disk size.

## What we should do for real JS budgets

Track raw file sizes manually, e.g. via a simple script:

```js
// scripts/check-bundle-sizes.js
import { statSync } from 'node:fs';
import { gzipSync } from 'node:zlib';
import { readFileSync } from 'node:fs';
import { glob } from 'glob';

const limits = {
  'aegov.esm.js': 15 * 1024,
  'aegov-input.entry.js': 8 * 1024,
  'aegov-datepicker.entry.js': 30 * 1024,
  'aegov-form-field.entry.js': 4 * 1024,
};

for (const file of Object.keys(limits)) {
  const buf = readFileSync(`dist/aegov/${file}`);
  const gz = gzipSync(buf).length;
  const status = gz > limits[file] ? 'OVER' : 'OK';
  console.log(`${status} ${file}: ${gz}B (limit ${limits[file]}B)`);
}
```

## Current size-limit scope

Only `aegov.css` is tracked because:
- It's a single bundled file (no lazy-load runtime).
- size-limit measures it correctly.
- It captures the design system's full theme + component CSS surface.

CSS budget: **60 KB** (currently ~6 KB). Wide ceiling reflects future
component growth (we expect more components in 0.3.0+).

## Run

```bash
npm run size
```
