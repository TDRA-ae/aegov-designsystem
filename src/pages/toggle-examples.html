API Reference

Properties

Property Attribute Type Default Description
fieldId field-id string auto Unique ID for the native checkbox element. Auto-generated if not provided.
name name string — The name attribute for the toggle, used in form submissions.
value value string — The value attribute for the toggle, included in the change event detail.
checked checked boolean false Whether the toggle is in the on/checked state.
size size 'sm' | 'base' | 'lg' 'base' The size of the toggle control and associated label text.
disabled disabled boolean false Disables the toggle. Reduces opacity and prevents interaction.
required required boolean false Marks the toggle as required. Sets aria-required="true".
label label string — Visible label text rendered at the inline-end of the toggle.
description description string — Description text below the label. Only rendered when label is provided. Linked via aria-describedby.

Events

Event Detail Description
aegovToggleChange { checked: boolean, value?: string } Emitted when the toggle state changes. Includes the new checked state and optional value.

Slots

Slot Description
icon-unchecked Icon displayed inside the thumb when the toggle is off. Typically an SVG element.
icon-checked Icon displayed inside the thumb when the toggle is on. Typically an SVG element.

Pass-through Attributes

The following attributes are passed through to the native <input> element: aria-*, data-*, form, tabindex, autofocus, title.

ARIA Attributes

  • The native input uses role="switch", which announces the element as a toggle switch to screen readers (e.g. "Dark mode, switch, off").
  • The visual track and thumb are marked with aria-hidden="true" so screen readers ignore the decorative elements.
  • When a label prop is set, the toggle is wrapped in a <label> element, associating the text with the input natively.
  • When no visible label is provided, use aria-label on the host element to give the toggle an accessible name (e.g. <aegov-toggle aria-label="Enable dark mode">).
  • When a description is provided, it is linked to the input via aria-describedby.
  • When required is set, the input receives aria-required="true".

Best Practices

  • Always provide an accessible name. Use either the label prop for a visible label, or aria-label for a visually hidden name. A toggle without either is inaccessible.
  • Use toggle for instant actions. Toggles should take effect immediately (e.g. enabling Wi-Fi). If the change requires a form submission, use a checkbox instead.
  • Avoid negative labels. Write labels as positive statements. Use "Enable notifications" instead of "Disable notifications" to avoid double-negative confusion when the toggle is off.
  • Icon slots are decorative. Icons in the thumb enhance the visual design but must not be the sole means of conveying state. The role="switch" and checked state already communicate the toggle's purpose to assistive technology.
  • Disabled toggles should explain why. If a toggle is disabled, provide context nearby (e.g. a tooltip or adjacent text) explaining why the control is unavailable.
  • Sufficient contrast. The default color scheme provides WCAG AA contrast for both on (primary-600 track) and off (aeblack-200 track) states against typical page backgrounds.
